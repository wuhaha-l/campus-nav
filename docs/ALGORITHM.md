# 核心算法说明

本文面向「讲清楚设计取舍」：既是设计报告的算法摘要，也是面试时可直接口述的版本。

## 1. 图建模

把校园抽象成**带权无向图**：

- 顶点：28 个地点 + 沿道路生成的路口节点（地点编号 1..28，路口从 29 开始）
- 边：地点间 / 路口间的道路，属性 `dist`（米）、`time`（步行秒数）、`metro`（是否地铁边）
- 存储：邻接表 `VertexNode v[]` + 边链表 `EdgeNode`

```c
typedef struct EdgeNode {
    int to;
    double dist, time;
    int metro;            /* 1=地铁边，只在地铁方式下通行 */
    struct EdgeNode *next;
} EdgeNode;
```

**为什么用邻接表**：校园路网是稀疏图，空间 O(n+m)；Dijkstra 松弛时只需沿链表遍历当前点的邻接边，不必扫描 n² 矩阵。

**为什么边权是时间**：需求是「最快路线」而非最短距离，边权统一为预估通行秒数。步行直接用 `time`；其他方式按 `距离 ÷ 速度 × 3600` 换算（km/h：步行 5、骑车 10、驾车 25、电动车 25、地铁 60）。

## 2. 状态扩展 Dijkstra

标准 Dijkstra 的状态是「节点 u」。本项目把状态扩展为 **`(来路 p, 节点 u)`**：

1. 起点状态 `(0, start)`，耗时 0，其余为 INF。
2. 每轮取未确定状态中耗时最小者；到达终点后，在所有到达终点的状态中取最小值。
3. 松弛边 `(u, v)`：若 `v` 是普通地点且非终点则跳过（路口路网下中间不经过其他地点，校门除外——校内去地铁口需经校门）。
4. 若 `p ≠ 0`，用叉积 `(u-p) × (v-u)` 判断是否转向；非共线加 **0.5 秒转弯罚时**。
5. 沿前驱数组回退还原路径，逆序输出。

### 为什么要扩展状态

宿舍区是横平竖直的网格路网，多条路径总耗时完全相同。标准算法在这些等时路径里随意挑一条，结果在网格里来回拐弯（「锯齿形路线」），看起来明显绕路。把「我从哪条边来的」纳入状态后，算法能识别转向代价，等耗时路线自动选更直的一条。

### 罚时为什么不破坏最优性

0.5 秒远小于任何真实绕行代价（最短绕行也在秒级以上），因此只会改变**等耗时路径之间的排序**，不会把真正更快的路线挤掉。状态数上限 `n × 8`，复杂度 `O((n+m) · 状态数)`。

### 地铁分层

地铁边带 `metro=1`，仅在地铁方式下松弛。4 个地铁口原本与校园路网不连通，为每个地铁口连一条到最近校门的步行边，并允许 Dijkstra 中间经过校门（其他地点不可作中转），得到「校内 → 校门 → 地铁口 → 地铁」的合理动线；地铁口之间还需校验是否属于同一段线路。

## 3. 真实路网构建

- 地图底图为实景图，坐标由标定工具点选生成，比例尺 `meterPerPx ≈ 1.334 米/像素`。
- 道路是弯曲的，直线连接会穿过楼体：沿道路描点存成折线 `roads_custom.dat`，加载时端点吸附到 8px 内已有路口，中间点生成新路口节点，地点自动连到最近路口。
- 绘制路线时沿折线画（`drawSegPolyline`），不会把弯路拉直。

## 4. BFS 路网质检（F1）

从地点 1 出发 BFS 遍历全图，统计不可达地点（地铁口只通地铁线路，不计入孤立）；扫描路口度数找断头路口；对每条路段折线逐像素检查是否穿过建筑（周围浅色路面像素占比过低判为穿楼）。

## 5. 自动化验证

课程设计中用 Python 脚本读取全部路网数据做回归断言：

- 28 个地点共 **276 对**两两可达
- 5 条地铁边方向正确、4 个地铁口都通过校门接入校园
- 地铁口对之间可直接导航

每次改路网后跑一次脚本，保证「任意地点对都有路可走」。配合 VS `/W3` 零警告编译与冒烟 / 边界测试用例。
